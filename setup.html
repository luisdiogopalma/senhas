Setup guide

You'll end up with two links: a Display link for the waiting-room screen (big gabinete numbers + your looping video), and a Control link that each nurse opens to call senhas from a number pad.

They sync live through Firebase, a free Google service. No coding — about 15 minutes, once.

Your files (keep them all in one folder): config.js, shared.js, display.html, control.html, settings.html, your video renamed to video.mp4, the DIN font files (.otf), and the two logo files (logo.svg, logo-light.svg).
1

Create the free Firebase project · ~4 min

  1. Go to console.firebase.google.com and sign in with a Google account.
  2. Click Create a project (or Add project).
  3. Name it, e.g. senhas-checkpointlx. Click Continue.
  4. Turn Google Analytics off (not needed). Click Create project, wait, then Continue.
This is the free Spark plan — no credit card. If anything suggests upgrading, ignore it; a few numbers use a tiny fraction of the free limits.
2

Turn on the Realtime Database · ~3 min

  1. Left menu: Build → Realtime Database.
  2. Click Create Database.
  3. Location: europe-west1 (Belgium) — closest to Portugal. Click Next.
  4. Choose Start in locked mode, click Enable.
  5. Open the Rules tab, replace everything with this, and click Publish:
{
  "rules": {
    "queue":    { ".read": true, ".write": true },
    "settings": { ".read": true, ".write": true },
    "message":  { ".read": true, ".write": true },
    "display":  { ".read": true, ".write": true },
    "meta":     { ".read": true, ".write": true }
  }
}
Honest note: these rules let anyone with your database link read/change the numbers and display settings. That's fine here — it holds only senha numbers and screen settings, no patient data, and the link isn't published. Want a shared password on top? Just ask.
3

Paste your settings into config.js · ~3 min

  1. Click the gear icon → Project settings.
  2. Under Your apps, click the </> (Web) icon.
  3. Give it a nickname, click Register app, and skip the hosting offer.
  4. You'll see a firebaseConfig block. Open config.js in Notepad/TextEdit and paste each value between the quotes, replacing every PASTE_HERE.
  5. Make sure databaseURL is filled — it looks like https://…-default-rtdb.europe-west1.firebasedatabase.app. If missing, copy it from the top of the Realtime Database page.
  6. While there, set your gabinete names and the header at the top of config.js. Save.
4

Add your video

Rename your video to exactly video.mp4 and keep it in the same folder.

  • No video yet? Fine — the screen shows the numbers full-size until you add one.
  • Over ~90 MB and hosting online? Shrink it with HandBrake (free), or use the local option in Step 5.
5

Put it online — pick one

Host it free recommended

  1. Create a free account at github.com.
  2. New repository → name it senhas → Public → Create.
  3. Click uploading an existing file and drag in every file in the folder — the HTML files, config.js, video.mp4, all the .otf fonts, and both logos. Commit changes.
  4. Settings → Pages → Source Deploy from a branch, Branch main / (root) → Save.
  5. After 1–2 min your links are:
    Display → https://YOUR-USERNAME.github.io/senhas/display.html
    Control → https://YOUR-USERNAME.github.io/senhas/control.html
A public repo means the files (including the video) are publicly viewable. Fine for a generic waiting-room video; if it's sensitive, use the local option.

Run it locally — even from a USB stick large / private video

If the screen is driven by a PC you control, the page and video can live entirely on that PC or on a USB pendrive plugged into it — the video never goes online:

  1. Copy the whole folder — display.html, config.js, the fonts, the logos and video.mp4 — into one folder on the PC or the pendrive.
  2. Double-click display.html, then press F11 for fullscreen. It finds video.mp4 next to it automatically (the drive letter doesn't matter). To change the video later, just replace video.mp4 in that folder.
  3. Keep the pendrive plugged in. The PC still needs internet — the senha numbers sync through Firebase.
  4. For staff, still host online but upload only config.js, control.html, the fonts and logos (tiny, no video) — every PC opens that control link. Both talk to the same Firebase.
On the local route the screen won't force itself awake, so set Windows to never sleep and turn off the screensaver (Settings → Power) so the display stays on.
6

Go live

Waiting-room screen: open the Display link and tap Iniciar ecrã once — that single tap turns on the sound and goes fullscreen (then it stays awake and hides the pointer). Bookmark it. After a reboot, tap it again — browsers require one tap before allowing sound.

Staff: open the Control link. Each nurse taps their gabinete once — it's remembered on that device, so it reopens straight to their pad. Type the senha and press Chamar ✓ (or type on the PC number pad and press Enter). ⌫ deletes a digit, Esc clears. After calling, the button turns amber to rechamar the same senha; typing a new number starts fresh.

Tip: give each room its own bookmark that opens directly to its pad by adding the number — e.g. …/control.html#3 opens Gabinete 3. Repor tudo a zero clears the board silently.

Everyday questions

Add, rename or switch off a gabinete?

Open settings.html (link at the bottom of the control page). The password is 6969. Everything there — rooms, grid, video, voice, chime, auto-clear — updates the waiting-room screen live.

Numbers not updating?

Check the connection dot. If it's red, the device lost internet, or a value in config.js has a typo — most often databaseURL.

No sound, or a Brazilian accent?

No sound → you didn't tap Iniciar ecrã, or the screen volume is down. Wrong accent → the display device has no European-Portuguese voice, so it fell back. On Windows: Settings → Time & language → Language → add Português (Portugal), then restart the browser (once). Turn either off with SOUND_ENABLED / SPEAK_ENABLED; change the words with ANNOUNCE_TEMPLATE.

Change the look?

Colours and fonts live at the top of display.html and control.html — or just ask.
